# The H100 session

One rented session, one purpose: bring back evidence that cannot be produced
anywhere else. Everything else in this repository runs on a laptop, and that is
the point — so the hour on a GPU is spent on the four things that genuinely
need one, in the order of what would hurt most to lose.

Nothing here is improvised. Every step is a command that already exists and has
been run on the laptop first.

---

## What the session is for

| # | artifact | why only here |
|---|----------|---------------|
| 1 | **cross-rule readback** — the post-validator's verdicts against a self-hosted NIM | NIM's guided decoding is not the hosted catalog's. Agreement across two decoders is evidence; a repeat on the same one is not. |
| 2 | **receipt digests on linux/amd64** | The reproducibility claim is scoped to one architecture until a second one prints the same hashes. |
| 3 | ~~a real build identifier in provenance~~ | Attempted 2026-08-27: NIM returns none either. The claim was wrong and is corrected in [readback.md](readback.md); nothing to collect here. |
| 4 | **video frames that name the stack** | `kubectl`, the mode chip reading `nim`, provenance with a build. Criterion (b) is earned here or not at all. |

What the session is **not** for: better answers, a faster demo, or anything the
pattern needs. The live URL stays on CPU and the hosted catalog, because a judge
running it without a GPU is the argument.

---

## Before the clock starts

None of this belongs in rented time.

- [ ] NGC account, API key issued, `docker pull` of the chosen NIM image
      completed **on any machine** — a session burned on authentication is the
      most common way this day fails.
- [ ] `model_id` fixed and present in both catalogs, so the readback compares a
      model with itself.
- [ ] Repository cloned on the target machine, `make test` green there.
- [ ] `docs/SHOOT.md` §1 done: clean browser profile, bare terminal prompt, no
      notifications, nothing in frame that names anything.
- [ ] Laptop-side digests to compare against, printed and kept:
      `python3 tools/arch_receipts.py`
- [ ] Counter reset with the launch date if this session is also the launch:
      `python3 tools/counter.py --reset <date> --reason "..."`

## Order of the session

Evidence first, video second. If the session ends early, a video can be reshot
on the hosted path; the readback cannot be produced at all.

### T+0:00 — bring the endpoint up

```bash
kubectl get pods                    # screenshot candidate
curl -s $NIM/v1/models | head       # the model is served
```

Do not proceed until a plain chat completion returns. If nothing serves by
**T+0:45**, stop and go to *Abort* below.

### T+0:15 — artifact 2, thirty seconds of work

```bash
python3 tools/arch_receipts.py | tee ~/arch-linux-amd64.txt
make test
```

Compare the digests against the laptop's, on the spot. Equal earns the wider
claim; different is the finding the repository has been holding a place for.
Either way it goes into the report — a difference is not a reason to stop.

### T+0:25 — artifact 1, the readback

```bash
make readback BASE_URL=$NIM/v1 RUNS=10
```

Writes `docs/readback.md`: receipts, the offline suite, and acceptance on this
path with its findings broken out by code. Two things to read the moment it
finishes:

- **the suite must be 35/35 with zero silently released.** It runs offline and
  does not touch the endpoint, so a difference here means the machine, not the
  decoder — investigate before anything else.
- **acceptance may differ from the hosted path, and that is the measurement.**
  A drop is not a defect to hide; a drop with new finding codes is the
  interesting case, because it says the two decoders disagree about shape.

### T+0:45 — artifact 3, provenance with a build

```bash
NVIDIA_BASE_URL=$NIM/v1 python3 -m explainer declared-laws --json \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["provenance"])' \
  | tee ~/provenance-nim.txt
```

If a build identifier comes back, the page will show it in place of
`n/a (api-catalog)` — screenshot that line.

### T+1:00 — buffer

Whatever diverged above gets fixed or written down here. Nothing new starts.

### T+1:30 — artifact 4, the takes

`NVIDIA_BASE_URL=$NIM/v1 make ui`, then follow **`docs/SHOOT.md` §3**, which
holds the shot list. Three frames exist only on this machine:

- `kubectl get pods` with the NIM pod running;
- the mode chip reading `nim` instead of `api-catalog`;
- the provenance line with a real build.

Hold the 3→4 transition through the flip rather than cutting on the click — the
chips travel amber to green and the values write themselves in. That is the shot
the demo is for.

### T+2:15 — teardown

```bash
kubectl delete ...            # or the console
```

Confirm the spend has stopped. Then, off the machine:

- [ ] `docs/readback.md` committed
- [ ] digests from both architectures compared and the README's scope line
      updated if the wider claim was earned
- [ ] video and screenshots checked at full size **looking only at the edges of
      the frame** — a terminal prompt, a namespace, a browser tab
- [ ] exported file metadata checked for a username or machine name

## Abort

The demo does not depend on this session. If NIM will not serve by T+0:45:

1. stop paying for the GPU;
2. shoot the video on the hosted path — every frame except the three above is
   identical, and the mode chip will honestly read `api-catalog`;
3. leave the README exactly as it is. It already claims Nemotron and NIM and
   says nothing about GKE, precisely so that a failed session costs a screenshot
   and not a correction.

That last line is the point of the whole arrangement: nothing published depends
on the session succeeding.
